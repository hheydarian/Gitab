## 📝 متن درسنامه و توضیحات تکمیلی

_ضریب اهمیت (Weight): ۳_

داوطلبان باید بتوانند دسترسی به فایل‌ها را از طریق استفاده صحیح از مجوزها (Permissions) و مالکیت‌ها (Ownerships) کنترل کنند.

### حوزه‌های دانش کلیدی

* مدیریت مجوزهای دسترسی روی فایل‌های معمولی، فایل‌های ویژه و دایرکتوری‌ها.
* استفاده از حالت‌های دسترسی مانند `suid`، `sgid` و `sticky bit` برای حفظ امنیت.
* آشنایی با نحوه تغییر ماسک ایجاد فایل (`umask`).
* استفاده از فیلد گروه برای اعطای دسترسی فایل به اعضای گروه.

### دستورات و اصطلاحات کلیدی

* `chmod`
* `umask`
* `chown`
* `chgrp`

## کاربران و گروه‌ها (Users and Groups)

یک سیستم لینوکسی می‌تواند کاربران و گروه‌های زیادی داشته باشد. شما می‌توانید با یک کاربر وارد سیستم شوید و با دستور `su` به کاربر یا گروه دیگری تغییر وضعیت دهید. هر کاربر به یک گروه اصلی (Primary Group) تعلق دارد و می‌تواند عضو گروه‌های دیگری هم باشد.

برای بررسی کاربر و گروه‌های خودتان از دستورات `whoami`، `groups` و `id` استفاده کنید:

```text
- $ whoami
jadi
- $ groups
jadi adm cdrom sudo dip plugdev netdev lpadmin sambashare debian-tor
- $ id
uid=1000(jadi) gid=1000(jadi) groups=1000(jadi),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),102(netdev),108(lpadmin),124(sambashare),125(debian-tor)
- $ su root -
Password:
- # id
uid=0(root) gid=0(root) groups=0(root)
- # exit
exit
- $ whoami
jadi
```

همانطور که می‌بینید، دستور `id` هم اطلاعات کاربر و هم اطلاعات گروه را نمایش می‌دهد.

> **نکته:** شناسه کاربری (`UID`) شماره `0` و شناسه گروه (`GID`) شماره `0` متعلق به کاربر `root` و گروه `root` است.

این اطلاعات در فایل‌های `/etc/passwd` و `/etc/group` ذخیره می‌شوند.

```text
$ cat /etc/group | grep adm
adm:x:4:syslog,jadi
lpadmin:x:108:jadi
```

## مالکیت و مجوزهای فایل (File ownership & permissions)

لینوکس برای هر فایل یا دایرکتوری از سه لایه دسترسی/مجوز استفاده می‌کند: کاربر مالک (User)، گروه (Group) و سایرین (Others).

هر فایل متعلق به یک کاربر و یک گروه است و آن کاربر و اعضای آن گروه، دسترسی‌های مشخص خواندن، نوشتن و اجرا روی آن دارند. به این نمونه نگاه کنید:

```text
$ ls -ltrh script.sh
-rwxr-xr-x 1 jadi adm 34 Mar  5  2023 script.sh
```

در مثال بالا، `jadi` مالک فایل است. فایل به گروه `adm` تعلق دارد و مالک (در اینجا `jadi`) مجوزهای خواندن (**r**ead)، نوشتن (**w**rite، شامل حذف و ویرایش) و اجرا (e**x**ecute، و در مورد دایرکتوری به معنای خواندن محتویات آن) را روی فایل دارد؛ در حالی که اعضای گروه `adm` و **سایرین (others)** فقط دسترسی خواندن و اجرا دارند.

<div class="book-img-frame" style="text-align: center; margin: 24px 0;"><img src="/Gitab/books/book13/assets/file_permissions.png" alt="" style="max-width: 100%; border-radius: 8px; border: 1px solid var(--g-border-dim);" loading="lazy"></div>

> **نکته:** در بسیاری از توزیع‌ها، وقتی کاربری را می‌سازید، سیستم گروهی با همان نام ایجاد می‌کند و فایل‌های آن کاربر را به همان گروه اختصاص می‌دهد.

جدول زیر اطلاعات بیشتری درباره بخش اول خروجی دستور `ls -l` نشان می‌دهد:

| موقعیت | معنا |
| :---: | :--- |
| ۱ | نوع ورودی را مشخص می‌کند. خط تیره (`-`) برای فایل‌های معمولی، `l` برای لینک‌ها و `d` برای دایرکتوری است. |
| ۲، ۳، ۴ | دسترسی خواندن، نوشتن و اجرا برای مالک (Owner) |
| ۵، ۶، ۷ | دسترسی خواندن، نوشتن و اجرا برای اعضای گروه (Group) |
| ۸، ۹، ۱۰ | دسترسی خواندن، نوشتن و اجرا برای سایر کاربران (Others) |
| ۱۱ | نشان می‌دهد که آیا روش‌های دسترسی دیگری (مانند SELinux) روی این فایل اعمال شده است یا خیر (جزو سرفصل آزمون LPIC 101 نیست). |

بیایید مثال دیگری را بررسی کنیم:

```text
$ ls -l /sbin/fdisk
-rwxr-xr-x 1 root root 267176 Oct 15 18:58 /sbin/fdisk
```

می‌بینیم که فایل `fdisk` توسط مالک آن (`root`) قابل خواندن، نوشتن و اجرا است. سایر کاربران (حتی اگر عضو گروه `root` باشند) فقط می‌توانند آن را بخوانند و اجرا کنند.

> **نکته:** اگرچه کاربران غیر `root` می‌توانند `fdisk` را اجرا کنند، اما این برنامه اگر ببیند کاربر غیرادمین آن را اجرا کرده، کار خاصی انجام نخواهد داد.

بیایید به مثال دیگری نگاه کنیم:

```text
$ ls -l /home/
total 12
drwxr-xr-x 160 jadi jadi 12288 Feb  7 11:44 jadi
```

کاراکتر اول `d` است، پس این یک دایرکتوری است. مالک (`jadi`) دسترسی خواندن، نوشتن و اجرا دارد، اما سایر اعضای گروه `jadi` و **سایرین** فقط دسترسی خواندن و اجرا روی این دایرکتوری دارند.

دسترسی اجرا (کاراکتر `x`) روی دایرکتوری به این معناست که کاربران می‌توانند وارد آن شوند و فایل‌های داخلش را ببینند؛ ببینید اگر یک دایرکتوری مجوز `x` نداشته باشد چه اتفاقی می‌افتد:

```txt
(with root user)
$ tree /tmp/FOO
FOO
├── Bar1
└── Bar2

$ ls -ld /tmp/FOO/
drw-r--r--. 2 jadi jadi 80 Mar 23 19:32 FOO/

(With other user)
$ ls -l FOO/
ls: cannot access 'FOO/Bar2': Permission denied
ls: cannot access 'FOO/Bar1': Permission denied
total 0
-????????? ? ? ? ?            ? Bar1
-????????? ? ? ? ?            ? Bar2
```

### تغییر مجوزها (Changing permissions)

با استفاده از دستور `chmod` می‌توانیم مجوزهای فایل‌ها و دایرکتوری‌ها را تغییر دهیم. دو روش برای گفتن خواسته‌مان به این دستور وجود دارد:

۱. استفاده از کدهای مبنای ۸ (اکتال / Octal)
۲. استفاده از کدهای کوتاه نمادین (Symbolic)

وقتی از کدهای اکتال استفاده می‌کنید، باید یک عدد در مبنای ۸ بسازید تا به `chmod` بگویید چه می‌خواهید. در این روش، `0` یعنی هیچ دسترسی، `1` یعنی اجرا (execute)، `2` یعنی نوشتن (write) و `4` یعنی خواندن (read). بنابراین اگر بخواهید دسترسی ***خواندن*** + ***اجرا*** بدهید، باید `4` + `1` یعنی `5` را بدهید. جدول زیر تمام ترکیب‌های ممکن را نشان می‌دهد:

| نمادین (Symbolic) | اکتال (Octal) |
| :---: | :---: |
| `rwx` | 7 |
| `rw-` | 6 |
| `r-x` | 5 |
| `r--` | 4 |
| `-wx` | 3 |
| `-w-` | 2 |
| `--x` | 1 |
| `---` | 0 |

بنابراین اگر بخواهید به مالک `rwx`، به گروه `rx` و به سایرین فقط `x` بدهید، باید از `751` استفاده کنید:

```text
$ ls -ltrh myfile
-rw-rw-r-- 1 jadi jadi 0 Feb  8 21:01 myfile
$ chmod 751 myfile
$ ls -ltrh myfile
-rwxr-x--x 1 jadi jadi 0 Feb  8 21:01 myfile
```

این کار ممکن است در ابتدا سخت به نظر برسد، اما ترکیب‌های بسیار پرکاربردی مثل `755` برای فایل‌های اجرایی عمومی یا `600` برای فایل‌های شخصی وجود دارد که خیلی زود دستتان می‌آید.

یک روش _ساده‌تر_ هم هست. در این روش `u` به معنای کاربر (user)، `g` به معنای گروه (group) و `o` به معنای سایرین (others) است. می‌توانید `+x` را اضافه کنید تا مجوز اجرا بدهید، `+r` برای مجوز خواندن و `+w` برای مجوز نوشتن. برای مثال `u+x` مجوز اجرا را به کاربر مالک می‌دهد. اگر بخواهید مجوزی را حذف کنید، از علامت `-` استفاده کنید؛ مثلاً `g-r` برای اینکه اعضای `group` نتوانند فایل را بخوانند:

```text
$ ls -ltrh myfile
-rwxr-x--x 1 jadi jadi 0 Feb  8 21:01 myfile
$ chmod u-x myfile
$ ls -ltrh myfile
-rw-r-x--x 1 jadi jadi 0 Feb  8 21:01 myfile
$ chmod +x myfile
$ chmod uo+xr myfile
$ ls -ltrh myfile
-rwxr-xr-x 1 jadi jadi 0 Feb  8 21:01 myfile
```

یکی از سوئیچ‌های بسیار رایج در `chmod` سوئیچ `-R` برای اعمال بازگشتی (Recursive) روی تمام فایل‌ها و زیردایرکتوری‌ها است. دستور زیر مجوز `read` تمام فایل‌های داخل `/tmp` را به همه کاربران می‌دهد:

```text
# chmod -R o+r /tmp
```

### تغییر مالک و گروه (Changing owner and groups)

اگر لازم باشد مالکیت یا گروه یک فایل یا دایرکتوری را تغییر دهید، از دستور `chown` استفاده کنید:

```text
$ ls -ltrh newfile
-rw-rw-r-- 1 jadi jadi 0 Feb  8 21:38 newfile
$ chown root:root newfile
chown: changing ownership of ‘newfile’: Operation not permitted
$ sudo chown root:root newfile
[sudo] password for jadi:
$ ls -ltrh newfile
-rw-rw-r-- 1 root root 0 Feb  8 21:38 newfile
```

یک سوئیچ رایج در اینجا هم `-R` است تا `chown` به صورت بازگشتی روی کل پوشه‌ها و زیرمجموعه‌ها اعمال شود.

اگر فقط بخواهید گروه یک فایل را تغییر دهید، می‌توانید از دستور `chgrp` استفاده کنید:

```text
$ sudo chgrp postgres newfile
$ ls -ltrh newfile
-rw-rw-r-- 1 root postgres 0 Feb  8 21:38 newfile
```

با دستور `usermod` هم می‌توان گروه‌های بیشتری به یک کاربر اختصاص داد:

```bash
$ sudo usermod -aG sudo jadi # will add jadi to the sudo group
```

از آنجا که کاربران می‌توانند عضو گروه‌های متعددی باشند، ممکن است هنگام ساخت فایل‌های جدید نیاز داشته باشند **گروه پیش‌فرض** خود را موقتاً تغییر دهند. برای این کار با دستور `groups` گروه‌ها را چک کنید و با `newgrp` گروه پیش‌فرض را تنظیم نمایید:

```text
$ touch newfile
$ ls -ltrh newfile
-rw------- 1 jadi jadi 0 Feb  8 21:53 newfile
$ groups
jadi adm cdrom sudo dip plugdev netdev lpadmin sambashare debian-tor
$ newgrp adm
$ touch newerfile
$ ls -ltrh new*
-rw------- 1 jadi jadi 0 Feb  8 21:53 newfile
-rw------- 1 jadi adm  0 Feb  8 21:54 newerfile
```

## حالت‌های دسترسی ویژه (Access modes)

یک سوال برای شما: اگر ما دسترسی نوشتن روی `/etc/passwd` یا `/etc/shadow` نداریم، پس چطور می‌توانیم رمز عبور خودمان را تغییر دهیم؟

به صورت عادی وقتی برنامه‌ای را اجرا می‌کنید، آن برنامه با سطح دسترسی _خود شما_ اجرا می‌شود. اما چه می‌شود اگر لازم باشد برنامه‌ای را با سطح دسترسی بالاتر اجرا کنید؟ مثلاً برای ایجاد تغییر در فایل‌های رمز عبور؟ برای این منظور لینوکس دو بیت ویژه برای فایل‌ها در نظر گرفته است: **suid** (set user id) و **sgid** (set group id). اگر این بیت‌ها روی یک فایل تنظیم شده باشند، آن فایل هنگام اجرا با سطح دسترسی **مالک** (یا **گروه**) فایل اجرا می‌شود، نه کاربری که دستور را فراخوانی کرده است.

```text
$ ls -ltrh /usr/bin/passwd
-rwsr-xr-x 1 root root 50K Jul 18  2014 /usr/bin/passwd
```

متوجه حرف `s` در _بیت اجرایی_ مجوزهای کاربر (و همین‌طور برای گروه) شدید؟ این یعنی وقتی هر کاربری این برنامه را اجرا کند، برنامه با سطح دسترسی مالک فایل (که `root` است) اجرا می‌شود و نه با شناسه آن کاربر.

با استفاده از `chmod` و `+s` یا `-s` (به جای `x`) می‌توانید `suid` و `sgid` را فعال یا غیرفعال کنید.

تا بحث اینجاست، اجازه دهید آخرین بیت ویژه را هم معرفی کنم. نامش **sticky bit** است و اگر تنظیم شود، فایل را در برابر ***حذف شدن*** مقاوم می‌کند. اگر sticky bit روی یک دایرکتوری تنظیم شده باشد، فقط مالک فایل (یا مالک دایرکتوری و `root`) می‌تواند فایل را پاک کند، حتی اگر سایرین دسترسی نوشتن در آن دایرکتوری داشته باشند. این ویژگی برای جاهایی مثل `/tmp` بسیار کاربردی است (همه در دایرکتوری `/tmp` دسترسی نوشتن دارند، اما نمی‌خواهیم دیگران فایل‌های ما را پاک کنند).

بیت چسبان (Sticky bit) با `t` مشخص می‌شود و در آخرین کاراکتر مجوزهای خروجی `ls -l` دیده می‌شود:

```text
$ ls -dl /tmp
drwxrwxrwt 13 root root 77824 Feb  8 21:27 /tmp
```

همانطور که می‌بینید، sticky bit تنظیم شده و اگرچه همه کاربران در این دایرکتوری دسترسی نوشتن دارند، اما نمی‌توانند فایل‌های یکدیگر را حذف کنند.

بیایید نحوه تنظیم این حالت‌های دسترسی را مرور کنیم:

| حالت دسترسی | اکتال | نمادین |
| :---: | :---: | :---: |
| `suid` | 4000 | `u+s` |
| `sgid` | 2000 | `g+s` |
| `sticky` | 1000 | `+t` |

> **نکته:** تنظیم `sgid` روی یک دایرکتوری باعث می‌شود هر فایل جدیدی که داخل آن دایرکتوری ساخته می‌شود، به صورت خودکار گروه (GID) همان دایرکتوری را به ارث ببرد.

## دستور umask

یک سوال نکته‌دار دیگر: مجوزهای یک فایل تازه ساخته‌شده چقدر است؟ وقتی یک فایل غیرموجود را `touch` می‌کنید چه اتفاقی می‌افتد؟ مجوزهای آن چه خواهد بود؟ این موضوع توسط `umask` تعیین می‌شود. این دستور به سیستم می‌گوید چه مجوزهایی (علاوه بر مجوز اجرا) **نباید** به فایل‌های جدید داده شود. به عبارت دیگر، تصور کنید همه فایل‌های جدید مجوز اکتال `666` (خواندن + نوشتن برای کاربر، گروه و سایرین) می‌گیرند؛ بنابراین یک `umask` برابر با `0002` (بله! ۴ رقم) عدد `2` (نوشتن) را برای سایرین کم می‌کند (`666 - 0002 = 664`):

```text
$ umask
0002
```

اگر لازم باشد `umask` را تغییر دهیم، با همین دستور انجام می‌شود:

```text
$ umask
0002
$ touch newfile
$ ls -ltrh newfile
-rw-rw-r-- 1 jadi jadi 0 Feb  8 21:38 newfile
$ mkdir newdir
$ ls -ltrhd newdir
drwxrwxr-x 2 jadi jadi 4.0K Feb  8 21:38 newdir
$ umask u=rw,g=,o=
$ touch newerfile
$ ls -l newerfile
-rw------- 1 jadi jadi 0 Feb  8 21:41 newerfile
$ umask
0177
```

> **نکته:** دقت کنید چطور از `u=rw,g=,o=` استفاده کردم تا دقیقاً به `umask` (یا `chmod`) بگویم چه مجوزهایی می‌خواهم.
