## ترکیب دستورات (Combining commands)

اگر می‌خواهید بیش از یک دستور را در یک خط اجرا کنید، آن‌ها را با `;` از هم جدا کنید. بنابراین دستور `cd /tmp; ls` ابتدا `cd /tmp` را اجرا می‌کند و بعد `ls` را. اما کاربردهای پیشرفته‌تری هم وجود دارد.

می‌توانید از زنجیره‌سازی با `&&` (به عنوان AND منطقی) و `||` (به عنوان OR منطقی) استفاده کنید. در حالت AND، به محض اینکه اجرای دستور اول با خطا مواجه شود، اجرا متوقف می‌شود. در حالت OR، دستور بعدی تنها در صورتی اجرا می‌شود که دستور اول شکست بخورد. دقیقاً مثل گیت‌های منطقی!

گیج‌کننده است؟ بگذارید دوباره توضیح دهم. سیستم همیشه تلاش می‌کند نتیجه کل زنجیره شما را *ارزیابی* کند. پس اگر `A && B` داشته باشید و `A` شکست بخورد، سیستم دیگر نیازی به آزمایش `B` ندارد (چون نتیجه کلی در هر حال False خواهد بود). همین منطق برای `A || B || C` هم برقرار است. اگر `A` به درستی کار کند، ارزیابی کلی True است، پس نیازی به آزمایش `B` یا `C` نیست. اما اگر `A` شکست بخورد، سیستم `B` را امتحان می‌کند و اگر `B` هم شکست بخورد، مجبور است `C` را امتحان کند.

ما از زنجیره‌سازی برای ایجاد جریان‌های منطقی استفاده می‌کنیم. به عنوان مثال:

```bash
$ cp backup.gzip /backups/ && rm backup.gzip
```

این دستور این‌طور کار می‌کند: فایل بکاپ را در آن مسیر کپی کن و فایل اصلی را **فقط در صورتی** حذف کن که کپی قبلی موفقیت‌آمیز بوده باشد.

### اسکریپت‌های شل (Shell Scripts)

ما می‌توانیم دستورات شل یا برنامه‌ها و همین‌طور کمی منطق یا حلقه را با هم ترکیب کنیم تا اسکریپت‌های کوچک یا بزرگ بنویسیم. اسکریپت‌های شل زمانی مفیدند که می‌خواهید برخی کارها را در قالب یک دستور بزرگ‌تر *خودکار* (Automate) کنید. مثلاً یک اسکریپت به نام `do_backup.sh` ممکن است چند فایل را در یک فایل فشرده کند، نام این فایل را بر اساس تاریخ و ساعت فعلی تغییر دهد، آن را روی یک سرور راه‌دور ذخیره کند و در نهایت فایل‌های قدیمی‌تر از یک ماه را پاک کند.

### شبانگ (Shebang)

در ابتدای اسکریپت‌ها خطی وجود دارد که با `#!` شروع می‌شود و با مسیر یک برنامه اجرایی که باید این اسکریپت را اجرا کند ادامه می‌یابد. به این خط **شبانگ (Shebang)** می‌گویند و همانطور که گفته شد، به شل می‌گوید برای اجرای این اسکریپت از کدام _مفسر_ استفاده کند.

> **نکته:** در بسیاری از زبان‌های برنامه‌نویسی (از جمله Bash و Python)، وجود `#` در ابتدای خط در اسکریپت نشان‌دهنده _کامنت (توضیح)_ است. آن را با _شبانگ_ (`#!`) اشتباه نگیرید.

معمولاً اسکریپت‌های شل را با `#!/bin/bash` یا `#!/bin/sh` اجرا می‌کنیم.

بقیه یک اسکریپت شل می‌تواند از اکثر دستوراتی که از قبل بلدید، به همراه برخی دستورات خاص‌تر «برنامه‌نویسی» مثل حلقه‌ها، آزمون‌های شرطی و امثال آن استفاده کند. این یک نمونه ساده است:

```bash
#!/bin/bash

echo
echo "We are learning! Wowww..."
echo
```

> **نکته:** `sh` یک شل پایه‌ای‌تر است اما با اکثر چیزهایی که درباره‌شان صحبت می‌کنیم سازگار است. گزینه‌های دیگری مثل `zsh` و `csh` هم وجود دارند، ولی آزمون LPIC بر پایه `bash` است.

### متغیرها (Variables)

قبلاً در بخش قبلی دیده‌اید که می‌توان متغیرها را به شکل `VARNAME=VALUE` تعریف کرد. این یک نمونه است:

```bash
#!/bin/bash

NAME=Jadi

echo
echo "$NAME is learning! Wowww..."
echo
```

> **نکته:** اگر لازم است در مقدار متغیرتان فاصله (Space) داشته باشید، می‌توانید از شکل `NAME="Jadi the geeking guy"` هم استفاده کنید.

اگر می‌خواهید در اسکریپت شل خود به آرگومان‌های خط فرمان دسترسی داشته باشید، از `$1`، `$2` و ... استفاده کنید. تعداد آرگومان‌های خط فرمان را هم می‌توانید از طریق متغیر `$#` پیدا کنید.

### جایگزینی دستور (Command substitution)

گاهی لازم است خروجی یک دستور را در یک متغیر ذخیره کنید یا به شکلی از آن استفاده کنید. برای این کار می‌توانید از `$(command)` یا به سادگی از `` `command` `` (بک‌تیک) استفاده کنید. به این دو نمونه نگاه کنید:

```bash
➜  FILES=$(ls -1) # the $FILES variable contains the list of all files

➜  ~ date +'%Y%m%d-%H%m'
20230408-1604
➜  ~ touch backup_`date +'%Y%m%d-%H%m'`.tar
➜  ~ ls
backup_20230408-1604.tar
```

### اجرای اسکریپت‌ها (Executing scripts)

در دنیای یونیکس/لینوکس، یک فایل برای اینکه قابل اجرا باشد باید مجوز اجرا داشته باشد! :D برای این کار از دستور `chmod` با `+x` استفاده کنید. بعد از این مرحله می‌توانید اسکریپت خود را با دادن مسیرش به شل اجرا کنید. توجه داشته باشید که لینوکس به صورت پیش‌فرض برای پیدا کردن دستورها داخل دایرکتوری فعلی نمی‌گردد؛ بنابراین اگر می‌خواهید اسکریپتی را در دایرکتوری فعلی اجرا کنید، باید بنویسید `./script_name.sh`.

یک روش دیگر برای اجرای اسکریپت این است که `sh` یا `bash` را با نام فایل اسکریپت به عنوان آرگومان اجرا کنید؛ یعنی `sh my_script.sh`.

در هر دو روش بالا، اسکریپت درون یک پردازش فرزند Bash اجرا می‌شود و پس از پایان به همان شل قبلی *برمی‌گردد*. اگر می‌خواهید این رفتار را تغییر دهید و شل فعلی را با برنامه‌ای که اجرا می‌کنید *جایگزین* کنید، از دستور درونی `exec` استفاده نمایید. سوئیچ `-c` این دستور، برنامه را در یک محیط کاملاً تمیز و خالی از متغیرهای محیطی اجرا می‌کند.

### شرط‌ها (Conditions)

تا اینجا فقط دستورات را یکی‌یکی پشت سر هم اجرا می‌کردیم. این خیلی _برنامه‌نویسی‌طور_ نیست. اگر قرار است در برنامه‌هایمان کمی _منطق_ داشته باشیم، به _شرط‌ها_ و _حلقه‌ها_ نیاز داریم. ابتدا شرط‌ها را با استفاده از دستور `if` بررسی می‌کنیم. نحوه استفاده از آن به این شکل است:

```bash
if [ condition ]
then
   do something
   do another thing
else
   do new things
   even funnier things
fi
```

> **نکته:** بخش `else` اختیاری است؛ همان `if`، `then` و `fi` به تنهایی کافی است.

شرط‌ها می‌توانند TRUE (درست) یا FALSE (نادرست) باشند. یک شرط خیلی ساده `if [ "Linux" = "Linux" ]` است. مسخره به نظر می‌رسد؟ می‌دانم، ولی صبر کنید؛ فعلاً فقط داریم ساختار نحوی (Syntax) را یاد می‌گیریم. لطفاً هنگام بررسی برابری دو رشته، به _فاصله‌ها (Spaces)_ و علامت `=` دقت ویژه‌ای داشته باشید:

```bash
#!/bin/bash

kernel=$(uname -s)
if [ $kernel = "Linux" ]
then
    echo YES. You are using a Linux
else
    echo "Not a linux :("
fi
```

دستور اصلی برای بررسی شرط‌ها دستور `test` است، اما چون خیلی زیاد استفاده می‌شود، یک میان‌بر برایش داریم. به جای `test condition` می‌توانید بنویسید `[ condition ]`.

| شرط | معنا |
| :---: | :--- |
| `"a" = "b"` | بررسی برابری دو رشته (در اینجا False برمی‌گرداند) |
| `"a" != "b"` | رشته `a` _برابر نیست_ با رشته `b` |
| `4 -lt 40` | آیا ۴ _کوچک‌تر از_ ۴۰ است (True) |
| `5 -gt 15` | آیا ۵ _بزرگ‌تر از_ ۱۵ است (False) |
| `5 -ge 5` | آیا ۵ _بزرگ‌تر یا مساوی_ ۵ است |
| `5 -le 3` | آیا ۵ _کوچک‌تر یا مساوی_ ۳ است |
| `9 -ne 2` | آیا ۹ _نامساوی_ با ۲ است (True) |
| `-f FILENAME` | آیا فایل `FILENAME` وجود دارد (و فایل معمولی است) |
| `-s FILENAME` | آیا فایل وجود دارد و اندازه آن بیشتر از صفر است |
| `-x FILENAME` | آیا فایل وجود دارد و قابل اجرا است |

### دستور `read`

با استفاده از `read` می‌توانیم ورودی کاربر را بخوانیم. به این مثال نگاه کنید:

```bash
#!/bin/sh

echo "what is your name?"
read NAME

echo "Hello $NAME"

if [ $NAME = "Jadi" ]
then
    echo "Oh I know you!"
else
    echo "I wish I knew you"
fi
echo "Bye"
```

می‌توانید با سوئیچ `-t` برای انتظار زمان محدود (Timeout) تعیین کنید و با `-p` یک متن راهنما (Prompt) نمایش دهید:

```bash
if read -t 10 -p "Server address?" SERVER
then
    echo "Connecting to the $SERVER ..."
else
    echo
    echo "Too late!"
fi
```

### حلقه‌ها (Loops)

در برنامه‌نویسی از حلقه‌ها برای تکرار بخشی از برنامه استفاده می‌شود. در Bash دو نوع حلقه داریم: `for` و `while`. حلقه `for` به ما اجازه می‌دهد بخشی از برنامه را به تعداد مشخصی تکرار اجرا کنیم. حلقه `while` زمانی استفاده می‌شود که می‌خواهیم بخشی از برنامه را *تا زمانی که* یک شرط خاص برقرار است تکرار کنیم.

#### حلقه `for`

نحوه نوشتن آن به این شکل است:

```bash
for VAR in SOME_LIST;
do
  some stuff with $VAR
  some other stuff
done
```

> **نکته:** به کلمات `in`، `;`، `do` و `done` دقت کنید.

در هر دور از حلقه، مقدار `VAR` برابر با یکی از عناصر `SOME_LIST` می‌شود. این `SOME_LIST` می‌تواند شامل اعداد، نام فایل‌ها، کلمات و غیره باشد:

```bash
for NUM in 1 2 3 4 5 6;
do
    echo $NUM
done
```

اما اگر لازم باشد از ۱ تا ۴۲ بشماریم چه؟ برای این کار دستور `seq` را داریم. دستور `seq 1 42` یا شکل کوتاه‌تر آن `{1..42}` به ما اجازه می‌دهد حلقه را ۴۲ بار اجرا کنیم.

اینجا می‌توانیم از متغیرهای غیرعددی هم استفاده کنیم. این یک کاربرد بسیار رایج است:

```bash
for FILE in $(ls);
do
    echo $FILE
    wc -l $FILE
done
```

#### حلقه `while`

ساختار آن به این شکل است:

```bash
while [ condition ]
do
    do something
    do anohter thing
done
```

> **نکته:** اگر شرط شما همیشه درست بماند، حلقه `while` تا _ابد_ اجرا می‌شود. به این حالت _حلقه بی‌نهایت (Infinite loop)_ می‌گویند و باید با `Ctrl+C` متوقفش کنید.

این هم یک نمونه:

```bash
VAR=52

while [ $VAR -gt 42 ]
do
    echo VAR is $VAR and it is still greater than 42
    let VAR=VAR-1
done
```

> **نکته:** به کاربرد `let` دقت کنید! اگر فقط بنویسید `VAR=1` و بعد `VAR=$VAR+1`، آن‌وقت مقدار `VAR` به صورت یک رشته متنی برابر با `1+1` خواهد شد!

### ارسال ایمیل به کاربر `root`

برای ارسال ایمیل لازم است بسته `mailutils` را نصب کنید. بعد از آن دستور `mail` ایمیل‌ها را ارسال می‌کند. با اجرای دستور زیر می‌توانید به کاربر `root` ایمیل بفرستید:

```bash
jadi@funlife:~$ mail root
Cc:
Subject: Hi there root
hello there. This is my mail
```

و `root` این ایمیل را دریافت خواهد کرد. او می‌تواند با دستور `mail` آن را بخواند.

اگر لازم است داخل یک اسکریپت ایمیل بفرستید، خیلی ساده کافی است بنویسید:

```bash
$ echo "Body!" | mail -s "Subject" root
```

## مقادیر بازگشتی (Returned values)

در دنیای یونیکس، برنامه‌ها وقتی کارشان تمام می‌شود یک مقدار عددی برمی‌گردانند. اگر با زبان C برنامه‌نویسی کرده باشید، همان `return 0` انتهای برنامه است. به طور معمول عدد `0` به معنای اجرای موفق است. این مقدار بازگشتی را می‌توان از طریق متغیر `$?` خواند و بررسی کرد:

```bash
jadi@ubuntuserver:/etc/skel$ touch /chert
touch: cannot touch '/chert': Permission denied
$ echo $?
1
$ touch /tmp/11
$ echo $?
0
$ test -e /
$ echo $?
0
$ test -e /nonexist
$ echo $?
1
$ dummycommand
dummycommand: command not found
$ echo $?
127
```

برای برگرداندن مقدار خروج از اسکریپت‌های شل خودتان، از دستور `exit` استفاده کنید؛ مثلاً `exit 0` برای یک خروج موفق.
