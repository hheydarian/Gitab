## 🎯 اهداف و سرفصل‌های این بخش

* **ضریب اهمیت در آزمون (Weight):** ۳
* **سرفصل‌های کلیدی آزمون:**
  - ارسال دستورات به لودر راه‌انداز (Boot Loader) و آرگومان‌ها به هسته (Kernel) در زمان بوت
  - تسلط کامل بر توالی مراحل بوت از BIOS/UEFI تا پایان راه‌اندازی سرویس‌ها
  - درک و مقایسه سیستم‌های راه‌انداز `SysVinit`، `systemd` و آشنایی با `Upstart`
  - بازرسی وقایع و خطاهای فرآیند بوت در فایل‌های لاگ با ابزارهای `dmesg` و `journalctl`

## 🔄 مراحل و چرخه بوت سیستم (The Boot Process)

درک فرآیند بالا آمدن سیستم بسیار حیاتی است، چرا که در این مرحله دسترسی به شل یا ابزارهای عیب‌یابی ندارید و اگر مشکلی پیش بیاید، باید دقیقاً بدانید رایانه در کدام مرحله متوقف شده است. چرخه بوت لینوکس در ۵ گام متوالی خلاصه می‌شود:

1. **آزمایش خودکار سلامت قطعات (POST):** سفت‌افزار مادربرد (BIOS یا UEFI) سلامت سخت‌افزارها مانند رم، پردازنده و چیپست‌ها را بررسی می‌کند.
2. **بارگذاری لودر بوت (Bootloader):** سفت‌افزار، لودر بوت (معمولاً GRUB در لینوکس) را از دیسک، فلش، شبکه یا پارتیشن ESP فراخوانی می‌کند.
3. **بارگذاری هسته و دیسک اولیه (Kernel & initramfs):** لودر بوت، ایمیج هسته لینوکس (`vmlinuz`) و دیسک اولیه رم (`initrd` یا `initramfs`) را در حافظه بارگذاری کرده و کنترل سیستم را به هسته می‌سپارد.
4. **آماده‌سازی فایل‌سیستم ریشه و راه‌اندازی فرآیند آغازین:** هسته پس از شناسایی نهایی درایورها، سیستم فایل ریشه (`/`) را مانت کرده و نخستین برنامه فضای کاربری یعنی پردازش **init** (با PID شماره ۱) را اجرا می‌کند.
5. **شروع سرویس‌ها:** برنامه init بقیه سرویس‌ها، شبکه‌ها، سرورها و واسط گرافیکی (یا کنسول لاگین) را مطابق پیکربندی بالا می‌آورد.

## 🎛️ لودر راه‌انداز (Bootloader) و پارامترهای کرنل

لودر بوت حداقل سخت‌افزارهای مورد نیاز را آماده کرده و سپس سیستم‌عامل را پیدا و اجرا می‌کند. استاندارد مرسوم در لینوکس **GRUB 2** است. 

در منوی گراب می‌توانید با فشردن کلید **`e`** پارامترهای زنده به خط فرمان بوت هسته بیفزایید:
* **ورود به حالت تک‌کاربره برای بازیابی سیستم (Single-User / Rescue Mode):** اضافه کردن عدد `1` یا حرف `S` یا `single` یا `systemd.unit=rescue.target` در انتهای خط کرنل.
* **تنظیم وضوح تصویر:** مثلاً `vga=792` (برای حالت 1024x768 با عمق رنگ ۲۴ بیت).
* **حذف صفحه انیمیشن برای دیدن لاگ‌ها:** حذف کلمات `quiet` و `splash`.

## 📋 پایش لاگ‌های بوت (dmesg و journalctl)

لینوکس در حین بوت گزارش کاملی از اتفاقات تولید می‌کند. این پیام‌ها به دلایل سرعت و عدم آماده بودن فایل‌سیستم در حافظه موقت حلقه‌ای هسته (**Kernel Ring Buffer**) ذخیره می‌شوند:

### ۱. دستور `dmesg`
برای مشاهده تمام پیام‌های ثبت‌شده در بافر حلقه‌ای هسته به کار می‌رود:

```bash
dmesg
dmesg -T       # نمایش زمان‌ها به صورت تاریخ و ساعت خوانا
dmesg -l err   # فیلتر کردن و نمایش فقط پیام‌های با سطح خطای Error
```

پس از بالا آمدن کامل سیستم، سرویس لاگ این اطلاعات را در فایل `/var/log/dmesg` یا `/var/log/boot.log` ذخیره می‌نماید.

### ۲. ابزار قدرتمند `journalctl` (مربوط به systemd)
در سیستم‌های امروزی از ابزار `journalctl` برای بازرسی گزارش‌های باینری ژورنال استفاده می‌شود:

```bash
journalctl -k         # فقط نمایش پیام‌های کرنل (معادل dmesg)
journalctl -b         # لاگ‌های مربوط به بوت جاری سیستم
journalctl -b -1      # لاگ‌های مربوط به یک بوت قبل‌تر
journalctl -u sshd    # فیلتر لاگ‌های مربوط به یک سرویس خاص مانند SSH
journalctl -n 20      # نمایش ۲۰ خط آخر لاگ
journalctl -xe        # نمایش خطاهای اخیر همراه با توضیحات تشریحی
```

## 🏁 سامانه‌های مدیریت پردازش آغازین (Init Systems)

پس از آماده شدن هسته، اولین پردازشی که اجرا می‌شود دارای **شناسه ۱ (PID=1)** است:

```bash
# ps -p 1
PID TTY TIME     CMD
1   ?   00:00:06 systemd
```

در تاریخ لینوکس سه سیستم init اصلی حضور داشته‌اند:
1. **SysVinit (سنتی):** بر اساس استاندارد System V یونیکس؛ از اسکریپت‌های متنی بش در `/etc/init.d/` و سطوح اجرایی (Runlevels) استفاده می‌کرد.
2. **Upstart (رویدادمحور):** توسط شرکت کانونیکال (توسعه‌دهنده اوبونتو) در سال ۲۰۰۷ طراحی شد، اما با ورود systemd کنار رفت.
3. **systemd (استاندارد امروزی):** سامانه مدرن، پرسرعت با قابلیت راه‌اندازی موازی سرویس‌ها که امروزه استاندارد پیش‌فرض تمام توزیع‌های مطرح است.

## ⚙️ مدیریت سرویس‌ها در systemd با `systemctl`

سامانه systemd بر پایه مفهوم **یونیت‌ها (Units)** کار می‌کند. انواع یونیت‌ها شامل `service` (سرویس‌ها)، `target` (اهداف بوت)، `socket`، `mount`، `timer` و ... هستند.

### دایرکتوری‌های محل قرارگیری یونیت‌ها (به ترتیب اولویت):
1. `/etc/systemd/system/`: پیکربندی‌های دستی مدیر سیستم (بالاترین اولویت)
2. `/run/systemd/system/`: یونیت‌های داینامیک زمان اجرا
3. `/usr/lib/systemd/system/` یا `/lib/systemd/system/`: یونیت‌های پیش‌فرض نصب‌شده توسط پکیج‌ها (پایین‌ترین اولویت)

### دستورات پرکاربرد مدیریت سرویس:
```bash
systemctl start sshd          # اجرای سرویس
systemctl stop sshd           # متوقف کردن سرویس
systemctl restart sshd        # بازراه‌اندازی سرویس
systemctl reload sshd         # بازخوانی فایل‌های تنظیمی سرویس بدون قطع اتصال
systemctl status sshd         # مشاهده وضعیت جاری سرویس
systemctl is-active sshd      # آیا سرویس فعال و در حال اجرا است؟
systemctl enable sshd         # فعال‌سازی اجرای خودکار سرویس در زمان بوت
systemctl disable sshd        # غیرفعال‌سازی اجرای خودکار در بوت
systemctl daemon-reload       # بازخوانی و اعمال تغییرات فایل‌های یونیت systemd
```

### دستور سنتی در سامانه SysVinit:
در سیستم‌های قدیمی مدیریت از طریق اسکریپت‌های داخل `/etc/init.d/` صورت می‌گرفت:
```bash
/etc/init.d/ssh status
/etc/init.d/ssh restart
```
