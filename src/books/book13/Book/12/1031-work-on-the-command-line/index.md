### پوسته‌ها (Shells) و Bash

شما دستورات خود را درون یک «پوسته» (Shell) وارد می‌کنید؛ پوسته رابط خط فرمان شماست و گزینه‌های مختلفی برای آن دارید. برای رسیدن به شل باید یا در حالت متنی وارد سیستم (Login) شوید، یا یکی از *شبیه‌سازهای ترمینال* (Terminal Emulators) را در محیط گرافیکی خود اجرا کنید. نمونه‌هایی از آن `gnome-terminal`، `konsole`، `xterm` و غیره هستند.

بعد از اجرای شبیه‌ساز ترمینال یا لاگین در حالت متنی، وارد پوسته می‌شوید و می‌توانید دستورات را صادر کنید. هرچند `bash` (مخفف GNU Bourne Again Shell) رایج‌ترین پوسته است، اما ممکن است از `zsh`، `dash`، `ksh`، `csh` و موارد دیگر هم استفاده کنید.

می‌توانید با دستور زیر بررسی کنید که دستور عمومی `sh` در سیستم شما به چه پوسته‌ای لینک شده است:

```text
$ readlink /bin/sh
```

یا مقدار متغیر `$SHELL` را به این شکل چک کنید:

```bash
echo $SHELL
```

پوسته `bash` یک سری دستورات *داخلی* (Internal / Builtin) دارد که بدون هیچ وابستگی خارجی آن‌ها را می‌فهمد (مثل `cd`، `break`، `exec` و ...)؛ اما اگر دستوری را درونی نشناسد، سعی می‌کند آن را به عنوان یک فایل اجرایی بیرونی پیدا و اجرا کند.

برای تشخیص این موضوع می‌توانید از دستور `type` استفاده کنید:

```text
[jadi@fedora ~]$ type cd
cd is a shell builtin
[jadi@fedora ~]$ type ls
ls is aliased to `ls --color=auto'
[jadi@fedora ~]$ type ping
ping is /usr/bin/ping
```

## دستورات `cd`، `pwd` و `uname`

### دستور `cd`

احتمالاً تا الان کلی دستور `cd` دیده‌اید :) این دستور برای تغییر دایرکتوری (*change directory*) به کار می‌رود، از جمله رفتن به `.` (دایرکتوری جاری) و `..` (دایرکتوری والد).

به دو روش می‌توانید به مسیر دایرکتوری‌ها اشاره کنید:

1. **مسیرهای مطلق (Absolute Paths):** مثل `/home/jadi/lpic1/lesson3.1`
2. **مسیرهای نسبی (Relative Paths):** مثل `lpic1/lesson3.1`. در این حالت، علامت `/` را در ابتدا نمی‌گذاریم؛ بنابراین `bash` تلاش می‌کند دایرکتوری `lpic1` را همین‌جایی که هستیم (به صورت محلی و نسبی) پیدا کند.

> **نکته:** کاراکتر `~` به معنای *دایرکتوری خانگی (Home Directory) کاربری است که دستور را اجرا می‌کند*.

همچنین می‌توانید `cd` را بدون هیچ پارامتری اجرا کنید که شما را به دایرکتوری خانگی‌تان می‌برد. پس هر ۳ دستور زیر دقیقاً یک کار انجام می‌دهند:

```bash
cd
cd ~
cd $HOME
```

### دستور `pwd`

دایرکتوری فعلی شما را نمایش می‌دهد:

```text
[jadi@fedora lesson3.1]$ pwd
/home/jadi/lpic1/lesson3.1
```

### دستور `uname`

اطلاعاتی درباره سیستم در اختیارتان می‌گذارد. سوئیچ‌های رایج آن عبارت‌اند از:

| گزینه (Option) | توضیح |
| :--- | :--- |
| `-s` | چاپ نام کرنل (اگر گزینه‌ای ندهید، پیش‌فرض همین است) |
| `-n` | چاپ نام گره یا همان نام میزبان (`hostname`) |
| `-r` | چاپ شماره نسخه انتشار (Release) کرنل. این گزینه اغلب همراه با دستورات مدیریت ماژول‌ها استفاده می‌شود |
| `-v` | چاپ اطلاعات نسخه دقیق (Version) کرنل |
| `-m` | چاپ نام سخت‌افزار ماشین (معماری CPU) |
| `-o` | چاپ نام سیستم‌عامل |
| `-a` | چاپ تمام اطلاعات بالا به صورت یکجا |

مثال:

```text
[jadi@fedora lesson3.1]$ uname -a
Linux fedora 5.14.0-60.fc35.aarch64 #1 SMP Mon Aug 30 16:30:42 UTC 2021 aarch64 aarch64 aarch64 GNU/Linux
```

## دریافت راهنما (Getting Help)

بیشتر دستوراتی که استفاده می‌کنیم یک دفترچه راهنمای بسیار کامل و خوب دارند که با دستور `man` در دسترس است. این دستور به صورت پیش‌فرض از صفحه‌بند `less` استفاده می‌کند و شامل مستندات، سوئیچ‌ها، پارامترها و جزئیات ابزارها و دستورات است.

با خواندن دفترچه راهنمای دستور `yes` خودتان را با `man` آشنا کنید:

```text
$ man yes
```

توجه داشته باشید که صفحات `man` در بخش‌های (کتاب‌های) مختلفی دسته‌بندی شده‌اند. می‌توانید با خواندن راهنمای خود `man` این بخش‌ها را ببینید:

```text
$ man man
$ man 5 passwd
```

## کاراکترهای خاص و Quoting / Escaping

در دنیای کامپیوتر، برخی کاراکترها معنای خاصی دارند. مثلاً در `bash`، کاراکتر `*` به تمام فایل‌ها بسط داده می‌شود (Expand می‌شود). در این مواقع، اگر می‌خواهید از خود کاراکتر بدون این رفتار خاص استفاده کنید، باید آن را *Quote* یا *Escape* کنید. در بسیاری از موارد این کار با قرار دادن یک کاراکتر `\` قبل از آن انجام می‌شود:

```text
$ echo 2 \* 3 = 6
2 * 3 = 6
```

فهرست کاراکترهایی که معنای خاصی دارند و هنگام استفاده در دستورات باید آن‌ها را Quote کنید عبارت‌اند از:

<div dir="ltr">

`* ?[]'"\$;&()|^<>`

</div>

لطفاً توجه کنید که در فهرست کاراکترهای بالا، کاراکتر فاصله (Space) هم وجود دارد.

> **نکته:** همان‌طور که می‌بینید، خود `\` هم معنای خاصی دارد؛ پس اگر می‌خواهید از خودِ بک‌اسلش (بدون کاربرد Escape آن) استفاده کنید، باید آن را با یک بک‌اسلش دیگر به صورت `\\` بنویسید.

علاوه بر Escape کردن، می‌توانید از `\` برای ساختن برخی کاراکترهای ویژه هم استفاده کنید. مثلاً چون نمی‌توانید کاراکتر *Return* را داخل رشته تایپ کنید، آن را با `\n` (خط جدید) می‌سازید:

```text
jadi@funlife:~$ echo -e "hello\nthere"
hello
there
```

برخی موارد دیگر عبارت‌اند از:

| دنباله فرار (Escape Sequence) | عملکرد |
| :--- | :--- |
| `\a` | هشدار / زنگ (Alert / Bell) |
| `\b` | بک‌اسپیس (Backspace) |
| `\c` | جلوگیری از چاپ خط جدید انتهایی (مشابه گزینه `-n`) |
| `\f` | پرش صفحه / Form feed (پاک کردن صفحه در نمایشگرهای ویدئویی) |
| `\n` | خط جدید (New line) |
| `\r` | بازگشت کالسکه (Carriage return) |
| `\t` | تب افقی (Horizontal tab) |

در `bash` می‌توانید از `\` برای شکستن یک دستور طولانی به چند خط هم استفاده کنید:

```text
$ echo You know slashes! But this \
is another \
usage
You know slashes! But this is another usage
```

## متغیرهای محیطی پوسته (Shell Environment Variables)

*متغیرهای محیطی* حاوی تنظیمات و اطلاعاتی درباره پوسته هستند. برای مثال، ویرایشگر پیش‌فرض شما در متغیر `EDITOR` تنظیم می‌شود. می‌توانید مقدار یک متغیر پوسته را به این صورت ببینید:

```text
[jadi@fedora ~]$ echo $EDITOR
/usr/bin/nano
```

با دستور `set` یا `env` هم می‌توانید تمام متغیرهای محیطی را ببینید.

در ادامه، تعدادی از پرکاربردترین متغیرهای محیطی `bash` را می‌بینید:

| نام متغیر | عملکرد |
| :--- | :--- |
| `USER` | نام کاربری که لاگین کرده است |
| `PATH` | فهرست دایرکتوری‌هایی که برای یافتن دستورات جست‌وجو می‌شوند (جداشده با دونقطه `:`) |
| `EDITOR` | ویرایشگر متنی پیش‌فرض |
| `HISTFILE` | مسیری که `bash` باید تاریخچه دستورات را در آن ذخیره کند (معمولاً `.bash_history`) |
| `HOSTNAME` | نام میزبان سیستم |
| `PS1` | شکل ظاهری خط فرمان (Prompt)! می‌توانید با آن بازی کنید و تغییرش دهید |
| `UID` | شناسه عددی کاربرِ لاگین‌کرده |
| `HOME` | دایرکتوری خانگی کاربر |
| `PWD` | دایرکتوری کاری فعلی |
| `SHELL` | نام پوسته |
| `$` | شناسه پردازش (PID) پوسته `bash` (یا برنامه) در حال اجرا |
| `PPID` | شناسه پردازشِ والدی که این پردازش را شروع کرده است |
| `?` | کد خروج (Exit Code) آخرین دستور اجراشده |

وقتی می‌خواهید به مقدار یک متغیر دسترسی پیدا کنید، باید علامت `$` را به ابتدای نام متغیر اضافه کنید:

```text
$ echo $USER $UID
jadi 1000
$ echo $SHELL $HOME $PWD
/bin/bash /home/jadi /home/jadi/lpic
```

برای تعریف یک متغیر محیطی جدید، تغییر یا حذف آن، می‌توانیم چنین کارهایی انجام دهیم:

```text
$ MYMOOD=happy
$ echo I am $MYMOOD
I am happy
$ MYMOOD="Even Happier" # space has a specific meaning
$ unset MM
```

اگر می‌خواهید برنامه‌های جدیدی که از این شل اجرا می‌شوند به متغیری که تعریف کرده‌اید دسترسی داشته باشند، باید آن را همراه با `export` تعریف کنید یا بعداً `export` نمایید:

```text
$ export MYMOOD
$ export YOURMOOD="Not Confused"
```

> **نکته:** تنظیمات سراسری `bash` در فایل `/etc/profile` نگهداری می‌شوند و هر کاربر نیز فایل‌های تنظیمات اختصاصی خود را در `~/.profile`، `~/.bash_profile` و `~/.bash_logout` دارد. اگر به یک تغییر دائمی نیاز دارید، تنظیماتتان را در این فایل‌ها اضافه کنید.

## مسیر (`PATH`)

وقتی دستوری را وارد می‌کنید، `bash` ابتدا چک می‌کند آیا دستور داخلی خودم است یا نه و اگر بود اجرا می‌کند. در غیر این صورت، سراغ مسیرهای موجود در متغیر `PATH` می‌رود و یکی‌یکی دنبال فایل اجرایی آن دستور می‌گردد. اگر پیدایش نکند خطا می‌دهد. اگر بخواهید برنامه‌ای را در یک مسیر مشخص اجرا کنید، باید مسیر آن را صراحتاً بنویسید:

```text
$ echo $PATH
/home/jadi/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games
```

اما اگر بخواهم دستور `tar` را اجرا کنم چه اتفاقی می‌افتد؟ بیایید با دستورات `which`، `type` و `whereis` بررسی کنیم:

```text
jadi@funlife:~$ which tar
/bin/tar
jadi@funlife:~$ type tar
tar is /bin/tar
jadi@funlife:~$ whereis tar
tar: /usr/lib/tar /bin/tar /usr/include/tar.h /usr/share/man/man1/tar.1.gz
```

یک مثال جالب‌تر دستور `ping` در فدورا است:

```text
[jadi@fedora ~]$ whereis ping
ping: /usr/bin/ping /usr/sbin/ping /usr/share/man/man8/ping.8.gz
[jadi@fedora ~]$ which ping
/usr/bin/ping
[jadi@fedora ~]$ /usr/sbin/ping 4.2.2.4
PING 4.2.2.4 (4.2.2.4) 56(84) bytes of data.
64 bytes from 4.2.2.4: icmp_seq=1 ttl=50 time=160 ms
```

> **نکته:** به همین دلیل است که وقتی می‌خواهید بگویید «برنامه `this_program` را از همین دایرکتوری فعلی اجرا کن»، می‌نویسید `./this_program`. با این کار دقیقاً به `bash` می‌گویید فایل کجاست؛ چون در لینوکس، دایرکتوری جاری (`.`) به طور پیش‌فرض جزئی از `PATH` نیست.

## تاریخچه دستورات (Command History)

پوسته `bash` تاریخچه دستورات را در فایل `~/.bash_history` ذخیره می‌کند. می‌توانید با `cat` محتوای آن را ببینید یا دستور `history` را اجرا کنید. همچنین می‌توانید از کلیدها و ترکیب‌های زیر برای دسترسی به دستورات قبلی استفاده کنید:

| کلید (یا ترکیب کلید) | کاربرد |
| :--- | :--- |
| کلیدهای جهت‌نما (بالا و پایین) | حرکت در میان دستورات تاریخچه |
| `Ctrl+R` | جست‌وجوی رو به عقب در تاریخچه |
| `Ctrl+O` | اجرای دستوری که با `Ctrl+R` پیدا کرده‌اید |
| `!!` | اجرای آخرین دستور |
| `!10` | اجرای دستور شماره ۱۰ در تاریخچه |
| `!text` | جست‌وجوی رو به عقب برای عبارت `text` و اجرای اولین دستور پیداشده |

> **نکته:** اگر می‌خواهید تاریخچه خود را پاک کنید، دستور `HISTSIZE=0` را اجرا کنید.

## خروج از پوسته (Exiting the Shell)

دستور `exit` از پوسته خارج می‌شود؛ دقیقاً معادل زدن `Ctrl+D`.

اگر دستوری را داخل پرانتز `(...)` اجرا کنید، آن دستور درون یک زیرپوسته (Sub-shell) اجرا می‌شود و دستور `exec` هم یک دستور را اجرا کرده و پوسته فعلی را می‌بندد.
