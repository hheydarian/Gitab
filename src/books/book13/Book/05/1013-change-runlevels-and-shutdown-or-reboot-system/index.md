## 🚦 مفهوم سطوح اجرایی (Runlevels) و تارگت‌های بوت (Targets)

سطوح اجرایی تعریف می‌کنند که سیستم لینوکس در حالت جاری به چه خدماتی دسترسی دارد و چه برنامه‌هایی مجاز به اجرا هستند؛ می‌توان آن را وضعیت‌های مختلف «حیات سیستم» دانست.

### اهداف بوت در سامانه مدرن systemd (Targets)
در systemd به جای شماره‌های سنتی ران‌لول، از فایل‌های تارگت با پسوند `.target` استفاده می‌شود که گروهی از سرویس‌های مرتبط را همزمان فراخوانی می‌کنند:

```bash
systemctl list-units --type=target
```

مهم‌ترین تارگت‌های استاندارد عبارتند از:
- `poweroff.target` (معادل ران‌لول ۰): خاموش کردن کامل سیستم
- `rescue.target` (معادل ران‌لول ۱ یا single): حالت تک‌کاربره برای تعمیرات و بازیابی؛ سیستم فایل‌های محلی مانت هستند اما شبکه غیرفعال است.
- `multi-user.target` (معادل ران‌لول ۳): محیط چندکاربره متنی همراه با شبکه کامل (حالت استاندارد سرورها).
- `graphical.target` (معادل ران‌لول ۵): محیط چندکاربره همراه با شبکه و رابط گرافیکی (GUI Desktop).
- `reboot.target` (معادل ران‌لول ۶): راه‌اندازی مجدد سیستم.
- `emergency.target`: حالت اورژانسی حداقلی؛ فقط سیستم‌فایل ریشه به صورت فقط‌خواندنی (Read-Only) مانت است و حتی سایر دیسک‌ها مانت نمی‌شوند.

### بررسی و تغییر تارگت پیش‌فرض:
```bash
# مشاهده تارگت پیش‌فرض بوت سیستم
systemctl get-default

# تغییر تارگت پیش‌فرض به محیط متنی سرور (Multi-User)
systemctl set-default multi-user.target

# تغییر تارگت پیش‌فرض به محیط گرافیکی دسکتاپ
systemctl set-default graphical.target
```

### تغییر وضعیت جاری بدون نیاز به ریبوت (Isolate):
با دستور `systemctl isolate` می‌توان سیستم را در همان لحظه به تارگت دیگری هدایت کرد:
```bash
systemctl isolate multi-user.target   # خروج از محیط گرافیکی و ورود به محیط متنی
systemctl isolate rescue.target       # ورود به حالت تعمیرات و نجات سیستم
```

## 🏛️ سطوح اجرایی سنتی در سامانه SysVinit

در سیستم‌های قدیمی مبتنی بر SysVinit، وضعیت‌های سیستم با ارقام ۰ تا ۶ شماره‌گذاری می‌شدند:
- **سطح ۰ (Runlevel 0):** خاموش کردن سیستم (Halt / Shutdown)
- **سطح ۱ (Runlevel 1 یا S یا s):** حالت تک‌کاربره (Single-User Mode) برای امور مدیریتی
- **سطح ۲ (Runlevel 2):** چندکاربره متنی بدون شبکه (در دبیان حالت گرافیکی کامل)
- **سطح ۳ (Runlevel 3):** چندکاربره کامل متنی با شبکه کامل
- **سطح ۴ (Runlevel 4):** سفارشی‌نشده و رزرو برای مدیر سیستم
- **سطح ۵ (Runlevel 5):** چندکاربره متنی و گرافیکی با شبکه (X11 Desktop)
- **سطح ۶ (Runlevel 6):** راه‌اندازی مجدد (Reboot)

### دستورات سنتی `runlevel` و `telinit`:
```bash
# مشاهده ران‌لول قبلی و ران‌لول جاری
runlevel
# خروجی N 3 یعنی ران‌لول قبلی وجود نداشته و ران‌لول فعلی ۳ است

# تغییر ران‌لول جاری به محیط گرافیکی
telinit 5
# یا دستور:
init 5

# خاموش کردن سیستم
init 0
```

در سامانه SysVinit، ران‌لول پیش‌فرض در فایل تنظیمی `/etc/inittab` با خطی شبیه به زیر تعیین می‌شد:
```text
id:5:initdefault:
```

> **هشدار مهم آزمون:** هرگز مقدار `initdefault` را در فایل `/etc/inittab` برابر با ۰ یا ۶ قرار ندهید؛ چرا که باعث می‌شود سیستم پس از روشن شدن بلافاصله خاموش یا وارد چرخه ریبوت مداوم شود!

## 🛑 متوقف‌سازی و خاموش‌کردن اصولی سیستم (Stopping the system)

بهترین و امن‌ترین روش برای خاموش یا ریبوت کردن سرور استفاده از دستور `shutdown` است. این دستور چند مزیت بسیار مهم دارد:
1. ابتدا پیامی همگانی به تمام کاربران لاگین‌شده می‌فرستد و زمان خاموشی را اعلام می‌کند.
2. از ورود کاربران غیر ریشه جلوگیری می‌نماید.
3. به فرآیندها سیگنال **`SIGTERM`** (سیگنال شماره ۱۵) ارسال می‌کند تا داده‌های باز خود را ذخیره کرده و به آرامی بسته شوند.
4. پس از مهلت تعیین‌شده (پیش‌فرض ۱ دقیقه)، سیگنال **`SIGKILL`** (سیگنال شماره ۹) ارسال می‌کند تا فرآیندهای باقی‌مانده متوقف شوند.

```bash
# خاموش کردن سیستم پس از ۱۰ دقیقه با پیام سفارشی
shutdown -h +10 "سرور برای ارتقای سخت‌افزار تا ۱۰ دقیقه دیگر خاموش خواهد شد"

# خاموش کردن فوری
shutdown -h now

# ریبوت کردن سیستم در ساعت مشخص (مثلاً ۲۳:۳۰)
shutdown -r 23:30 "ریبوت برنامه‌ریزی‌شده شبانه"

# لغو خاموشی برنامه‌ریزی‌شده
shutdown -c "خاموشی سرور لغو گردید"
```

### دستورات سریع دیگر:
* `halt`: تمام پردازش‌ها را متوقف و فعالیت پردازنده را متوقف می‌کند.
* `poweroff`: سیستم را خاموش کرده و سیگنال ACPI برای قطع کامل برق مادربرد صادر می‌کند.
* `reboot`: سیستم را مجدداً راه‌اندازی می‌کند.
*(در سیستم‌های مبتنی بر systemd، این دستورات پیوند نمادین به ابزار `systemctl` هستند).*

## 📢 اطلاع‌رسانی به کاربران در سیستم (Notifying Users)

در سرورهای لینوکسی که چندین کاربر همزمان از طریق SSH به آن متصل هستند، اطلاع‌رسانی قبل از تغییرات مهم یا خاموشی الزامی است:

1. **دستور `wall` (مخفف Write All):** پیامی را بلافاصله بر روی صفحه ترمینال تمامی کاربران حاضر در سیستم چاپ می‌کند:
   ```bash
   wall "لطفاً کارهای خود را ذخیره کنید؛ سرور تا ۵ دقیقه دیگر ریبوت می‌شود."
   ```
2. **فایل `/etc/issue`:** متنی که **قبل از ورود** به کاربران ترمینال محلی (TTY) نمایش داده می‌شود (مثلاً نام توزیع یا هشدار امنیتی).
3. **فایل `/etc/issue.net`:** متنی که قبل از ورود به کاربران متصل از طریق شبکه (SSH یا تلنت) نشان داده می‌شود.
4. **فایل `/etc/motd` (مخفف Message of the Day):** پیامی که **بلافاصله پس از لاگین موفق** به کاربر نمایش داده می‌شود (مثلاً اخبار سازمان، رویدادها یا شرایط استفاده از سرور).
5. **دستور `mesg`:** تعیین می‌کند آیا کاربر مایل است پیام‌های سایر کاربران را در ترمینال خود دریافت کند یا خیر (`mesg n` برای غیرفعال‌سازی و `mesg y` برای فعال‌سازی). البته پیام‌های صادرشده توسط کاربر ریشه یا دستور `shutdown` توجهی به `mesg n` نکرده و همیشه نمایش داده می‌شوند.
